# Plain-English glossary

| Term | Meaning |
| --- | --- |
| **Symbol / ticker** | Short exchange identifier for a security, such as `AAPL`. |
| **OHLCV** | Open, high, low, close, and volume for one period of trading. |
| **Candle / bar** | One period's OHLCV record, e.g., one day. |
| **ETF** | Exchange-traded fund holding a collection of assets. It can still lose value. |
| **API** | A documented way for one program to request information from another. |
| **JSON** | Common text format for exchanging structured values. |
| **RSS** | A feed that websites publish for updates and headlines. |
| **SQLite** | Small database saved as a local file, included with Python. |
| **Migration** | Versioned change to the shape of database tables. |
| **Rate limit** | Maximum number of requests a service allows in a period. |
| **Idempotent** | Safe to run twice without creating duplicates or repeated trades. |
| **Time zone** | Interpretation of a timestamp; market schedules use exchange-local time. |
| **Look-ahead bias** | Accidentally using future information in an old trading decision. |
| **Survivorship bias** | Testing only securities that still exist and ignoring failures. |
| **Backtest** | Simulation of a strategy on historical information. |
| **Out-of-sample** | Dates reserved for evaluating a strategy, not tuning it. |
| **Paper trading** | Simulated orders using imaginary money. |
| **Signal** | An explainable suggestion to buy, sell, or hold. |
| **Order** | Request sent to a broker; it might fill, partially fill, or be rejected. |
| **Position** | Amount of a security held by the portfolio. |
| **Realized P&L** | Profit or loss recorded after selling, net of relevant costs. |
| **Unrealized P&L** | Current estimated gain or loss on holdings not yet sold. |
| **Drawdown** | How far a portfolio fell from an earlier high. |
| **Slippage** | Difference between the price you expected and got. |
| **Spread** | Difference between the best available buy and sell prices. |
| **Reconciliation** | Comparing your records with the broker's records and resolving differences. |
| **Inference** | Running an already-trained model on new data. |
| **Fail closed** | Refuse an operation when safety-critical data or a check is unavailable. |
